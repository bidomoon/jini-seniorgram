# 열린 작품의 음성·저장·공유 보완

2026-11-15. 카카오 로그인·AI 생성·상용 결제는 여전히 별도 연결과 실제 검증이 필요합니다.

## 변경

- 보관함에서 작품을 열고 ‘말로 저장 · 공유 안내’를 누르면 같은 작품 위에 음성 창이 열립니다. 마이크를 누르기 전에는 듣지 않습니다. ‘카톡으로 보내줘’, ‘사진첩에 저장해줘’를 확인하면 현재 열린 파일의 안내로 연결합니다. 실제 저장과 외부 전송은 별도의 버튼·기기 창에서 사용자가 마칩니다.
- 하나의 음성 패널을 이동해서 쓰고 닫을 때 제자리로 돌립니다. 중복 ID를 만들지 않으며 취소·창 닫기·페이지 이동 시 듣기를 중지합니다. 선택한 작품을 닫으면 파일 선택 상태도 해제합니다.
- `media-actions.js`가 저장·공유 중복 실행, 취소, 미지원, 실패 상태를 처리합니다. 공유 창의 선택 완료를 수신자 전송 완료로 표현하지 않습니다.
- 다운로드 링크는 저장 요청 안내만 표시합니다. 다운로드 완료 여부를 브라우저에서 확인할 수 없는 경우 저장 완료라고 하지 않습니다.
- `showSaveFilePicker`가 있는 브라우저에는 ‘저장 위치 골라 저장하기’를 제공합니다. 버튼의 실제 사용자 조작에서만 기기 창을 열고, 선택한 파일의 쓰기와 닫기가 모두 끝나야 완료를 표시합니다. 쓰기 실패는 중단하고 다운로드·공유 대안을 안내합니다. 파일 선택 중 페이지를 바꾸면 뒤늦게 파일을 쓰지 않습니다.
- 파일 형식에서 확장자를 정하고 이름의 경로·제어 문자를 제거합니다. 허용된 이미지·영상 외 파일은 저장·공유 요청을 거절합니다. 미리보기 URL과 공유창 URL을 닫기·이동 시 해제합니다.

## 검증

전체 14개 회귀 테스트, TypeScript, 프레임워크 및 Netlify 빌드가 로컬에서 통과했습니다. `tests/media-actions.cjs`는 파일 쓰기·닫기, 취소·실패·중복 방지와 오래된 파일 선택 차단을 가상 기기 API로 확인합니다. `tests/studio-local-flow.cjs`는 실제 앱 코드와 보관함·음성 창·저장 및 카카오톡 공유 안내를 함께 검사합니다.

이 테스트는 실제 디스크 쓰기, 실제 발화 인식률, 휴대폰 수신자 전송의 증거가 아닙니다. 배포 후 연결된 같은 Chrome 브라우저에서 화면·파일 연결·실패 복구를 추가 확인합니다. 실제 기기 쓰기와 전송은 별도로 확인해야 합니다.

## 근거

- [Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access): 사용자 조작에서 저장 창을 열고 `createWritable`의 쓰기·닫기 순서를 따릅니다.
- [W3C Web Share API](https://www.w3.org/TR/web-share/): 일시적 사용자 활성화, 중복 공유와 취소 오류를 구분합니다.
